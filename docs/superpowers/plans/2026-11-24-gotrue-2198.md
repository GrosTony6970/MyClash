# GoTrue 2.195 → 2.198 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run `supabase/gotrue:v2.198.0` in prod and dev with every GoTrue answer the API relies on
proven on a real 2.198 first.

**Architecture:** A throwaway probe (scratch, never committed) starts GoTrue 2.195 and 2.198 side by
side, each with its own postgres, and replays every behaviour the API pins. Its table is appended
to the spec. Differences become code fixes with red-first tests; unchanged claims are re-dated.
Then the image tag, docs and the connector e2e change.

**Tech Stack:** Docker (scratch compose project), Node 26 `fetch` probe script, NestJS API (vitest),
Playwright e2e, compose files.

**Spec:** `docs/superpowers/specs/2026-11-24-gotrue-2198-design.md`

**Branch:** `feat/mcp-server` in worktree `.claude/worktrees/mcp-server` (ruling 956: never switch
the shared folder). Commits on this branch; push at the end; PR #110.

## Global Constraints

- Target image: `supabase/gotrue:v2.198.0` exactly, in `infra/docker-compose.prod.yml:239` and
  `infra/docker-compose.dev.yml:152`. No other image changes.
- The probe's containers, networks and volumes use the compose project name `gotrue-probe` and never
  a `myclash-*` name; they are removed (`docker compose -p gotrue-probe down -v`) when the probe
  ends. The probe's files live in the session scratchpad, not the repo.
- Probe postgres: `supabase/postgres:17.6.1.160` (prod's image, `docker-compose.prod.yml:162`).
- Probe GoTrue env mirrors prod's auth-relevant values (`GOTRUE_JWT_EXP=3600`, password policy,
  `GOTRUE_MAILER_AUTOCONFIRM=false`, refresh rotation on, reuse interval 10, the OAuth server keys
  slice 1 added: enabled, DCR on, `AUTHORIZATION_PATH=/oauth/consent`, issuer set) with a throwaway
  `GOTRUE_JWT_SECRET`; SMTP pointed at nothing reachable (the probe uses admin calls, not mail).
- A comment that stays true on 2.198 is re-dated to `read on GoTrue v2.198.0` (or `probed on`).
  A comment that is no longer true is a finding, not a re-date.
- Connector e2e: `GET {issuer}/user` with a connector token stays asserted 200, with a message
  naming GoTrue's announced removal; `PUT {issuer}/user` and `GET {issuer}/user/oauth/grants` with a
  connector token → 403 with `error_code` (or `code`) `no_authorization`.

## Review Focus

1. **A reset link no longer leaves the old password working.** 2.198 "clear existing password on
   recover": a person who opens a reset link and closes the tab may lose their password. The probe
   (P8) records it; if true, Task 2 decides from the result (see Task 2's rule) — the person must
   not be told "your password still works" anywhere.
2. **An address another account holds may stop answering 500.** If 2.198 answers 422
   `email_exists`, the email-change door's "ask who holds it after a 500" path never fires (P3).
3. **Identities on a password-less account.** 2.196 can add an `email` identity when a first
   password is set; `signsInWithPassword` reads "password = email identity" (P6).
4. **The admin password write may stop ending the caller's own session** (P4) — then the door's
   re-sign-in is harmless but its comment is wrong.
5. **Connector refresh** — the refreshed access token keeps `client_id`, and the plain
   `/token?grant_type=refresh_token` either refuses a connector refresh token or keeps `client_id`
   (P11) — the slice-1 final review's I2, proven on the server itself.
